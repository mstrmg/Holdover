# Gun animation timelines (format spec)

Every gun action (firing, racking, reloads, checks, safety, malfunction clears, draw) is a **text timeline** that the game code plays. Nothing is a binary animation asset, so Claude can write and fix every move, and every number can be tuned without re-exporting anything. This follows the CLAUDE.md rule that hand and gun motion is procedural, with IK.

- Files: `Holdover/Data/GunAnims/<GunId>.json`, one per gun. GunId is the skeletal mesh name without `SK_`: `Pistol_M9`, `Pistol_1911`, `Rifle_AK`, `Rifle_FAL`, `Carbine_AR`.
- Generated by `tools/anim/gen_gun_anims.py` (run `python tools/anim/gen_gun_anims.py` from the repo root; it rewrites all five files and checks them). Edit the generator, not the JSON, so shared moves stay consistent across guns.
- Body and hands: Unreal's free UE5 mannequin ("Manny") in the full-body first-person setup. Arms reach the hand targets with two-bone IK; fingers are posed by blending the named finger poses, whose curls are defined in the game code.
- Checking: `tools/anim/preview_blender.py` plays a timeline on the exported gun in Blender (gun bones plus simple hand markers) and renders check frames.

## Units and spaces

- Lengths in **millimetres**, angles in **degrees**, time in **seconds**.
- **Gun space** is the gun's own model space from `docs/weapons/<gun>.md`: X forward along the bore, Y to the gun's **left**, Z up, right-handed (Blender convention). All positions are absolute in this space (no socket offsets). The game mirrors Y when it loads the file.
- **Camera space**: origin at the eye, X forward, Y left, Z up. Used for moves away from the gun (bringing a mag up to the eye) and for the whole-gun offset.
- **Body space**: origin at the pawn root between the feet, X forward, Y left, Z up. Used for the belt: mag pouches and holster.
- **Rotations are always axis + angle**: `{"axis": [x, y, z], "deg": d}`, axis a unit vector in the track's space, right-hand rule. Never Euler angles, so the mirror stays exact. A single-axis move keeps its sign (for example a hammer going from 0 to -60 degrees about Y), so a curve passes cleanly through zero.

## File layout

```json
{
  "gun": "Pistol_M9",
  "version": 1,
  "hold": { ... },
  "states": { ... },
  "actions": { "Fire": { ... }, "RackSlide": { ... } }
}
```

### Keys

Every animated value is a list of keys `{"t": seconds, "v": value, "ease": "linear" | "smooth" | "step"}`. `ease` says how the value travels **from this key to the next** (`smooth` = smoothstep, slow start and stop; `linear` = constant speed, used for spring-driven parts; `step` = jump at the next key). Before the first key a track holds the first value; after the last key it holds the last value.

`"v": null` on a track's **first** key means "whatever this bone was at when the action started" (a hammer that may be down or already cocked when the slide is racked). It never appears elsewhere.

Where the generator combines moves with different curves (for example recoil kick and roll peaking at slightly different moments) it writes them as linear keys sampled at 60 per second. That is expected, not a mistake.

### `hold`: the resting grip

Where the hands sit when no action is playing: `handR` and `handL`, each `{"space": "gun", "pos", "fingersDir", "palmNormal"}`, plus `fingersR` and `fingersL`, lists of `{"pose", "weight"}`.

- `pos` is the **centre of the palm**. The game finds the wrist (the IK target) by stepping back along `-fingersDir` and slightly along `-palmNormal` (tunable on the player component).
- `fingersDir` is a unit vector from the wrist toward the middle knuckle; `palmNormal` is a unit vector pointing **out of the palm**, square to `fingersDir`.

### Finger poses

Only these names are used. The game defines the curls; weights blend.

| Pose | Used for |
|---|---|
| `Grip` | Shooting hand around a pistol grip, index finger straight along the frame. |
| `IndexTrigger` | Index finger on the trigger (blend 0..1 for the press). |
| `SupportWrap` | Support hand wrapped over the shooting hand (pistol) or around a handguard (rifle). |
| `PinchRack` | Thumb and the side of the index pinch the slide serrations or a charging handle. |
| `OverhandRack` | Whole hand over the top of a pistol slide, fingers on one side, heel of the palm on the other. |
| `PalmMag` | Hand cupped around a magazine body, index finger along the front. |
| `ThumbPress` | Thumb extended to push a lever or button (safety, slide stop, mag release). |
| `Relaxed` | Open hand. |

### `states`: mechanical positions

Bone poses for each mechanical state, so the game can put the gun straight into a state (spawning, loading a save, snapping after an action is skipped) without playing a timeline. Each bone gives `loc` (offset from its rest pose, gun space) and/or `rot` (axis + degrees about the bone's pivot). Example: `"SlideLocked": {"Slide": {"loc": [-58, 0, 0]}, "Barrel": {"loc": [-9, 0, -1.5]}, "SlideStop": {"rot": {"axis": [0, 1, 0], "deg": 8}}}`. A state lists only the bones it changes; the opposite state (`SlideHome`, `HammerDown`, `SafetyOff`, `BoltHome`, `MagIn`) sets them back.

### `actions`

```json
"RackSlide": {
  "duration": 0.78,
  "holdAt": 0.36,
  "bones":  { "Slide": { "loc": [ {"t": 0.22, "v": [0, 0, 0], "ease": "smooth"}, {"t": 0.36, "v": [-60, 0, 0], "ease": "linear"} ] },
              "Hammer": { "rot": [ {"t": 0.22, "v": null, "ease": "linear"}, {"t": 0.27, "v": {"axis": [0, 1, 0], "deg": -60}, "ease": "smooth"} ] } },
  "gun":    { "pivot": "GripHand", "loc": [ ... ], "rot": [ ... ] },
  "handL":  [ {"t": 0, "hold": true, "ease": "smooth"},
              {"t": 0.22, "space": "gun", "pos": [18, 0, 29], "fingersDir": [0, -0.99, -0.15], "palmNormal": [0, 0.15, -0.99], "ease": "smooth"} ],
  "fingersL": [ {"t": 0, "pose": "SupportWrap", "weight": 1, "ease": "smooth"}, {"t": 0.1, "pose": "SupportWrap", "weight": 0, "ease": "smooth"} ],
  "attach": [ {"t": 0.25, "hand": "handL", "bone": "Magazine"}, {"t": 1.3, "hand": "handL", "bone": null} ],
  "events": [ {"t": 0.33, "name": "SlideToRear"}, {"t": 0.38, "name": "InBattery"} ]
}
```

- `duration`: total length in seconds. The player can scale time per action (a skill or speed setting).
- `holdAt` (optional): with full manual controls, playback pauses at this time while the action's key stays held, then carries on when it is released (the slide stays at the rear until R is let go; the mag stays in view during a mag check). Chained drills (`TapRack`, `ReloadEmpty`, `ClearDoubleFeed`) never pause.
- `bones`: per gun bone, `loc` keys (`v` = `[x, y, z]` offset from the rest pose, gun space) and/or `rot` keys (`v` = axis + degrees about the bone's pivot, gun-space axis). A bone keeps its last value after the action ends (a slide that ends locked back stays back) until another action or state keys it.
- `gun`: offset of the whole gun from the hold, in **camera space**, rotating about the `pivot` socket. `loc` keys move it; `rot` keys turn it (an axis along X rolls it, along Y tips the muzzle, along Z turns it left or right). Every action starts and ends with this offset at zero. The shooting hand follows the gun.
- `handL`, `handR`: hand keys. Each key has `t` and `ease`, then either `"hold": true` (the resting grip) or a full target: `space` (`gun`, `camera` or `body`), `pos`, `fingersDir`, `palmNormal`. Between keys the player converts both keys to camera space, then interpolates position (with the key's ease) and rotation (slerp). A hand with no list stays on its hold.
- `fingersL`, `fingersR`: finger pose weight keys `{"t", "pose", "weight", "ease"}`. Each pose is its own track (a key interpolates toward the next key **of the same pose**); a pose with no keys keeps its hold weight.
- `attach`: what a hand is carrying. From the moment a bone is attached until it is let go (`"bone": null`) it follows the hand, keeping the offset it had to the hand when it was picked up, and the bone's own keys are ignored (the generator leaves them out). When it is let go it goes back to its own track, which for a magazine is the seated position. A mag picked up at `MagFromPouch` is a fresh one from the pouch; a mag still in the hand at `MagStow` goes into the pouch.
- `events`: the gun state machine listens for these and decides what actually happens (for example what comes out of the chamber). Names:
  - `ShotBreak` (the round fires: bullet, muzzle flash, recoil impulse), `HammerDrop`, `HammerCock`, `TriggerReset`
  - `SlideToRear` (the slide or bolt reaches the rear: extraction and ejection point), `InBattery` (the slide or bolt closes: feed point)
  - `SlideLock`, `SlideRelease`, `BoltLock`, `BoltRelease`, `DustCoverOpen`
  - `MagDetach` (the mag unlatches), `MagDrop` (let go: becomes a physics prop), `MagStow`, `MagFromPouch`, `MagAttach`, `MagSeat`
  - `MagCheckView`, `ChamberView` (the player can see the rounds or the chamber), `ClearMalfunction`
  - `SafetyOn`, `SafetyOff`
  - `HolsterOut`, `HolsterIn`, `Shouldered`, `LowReady`
  - `Sound:<Name>`, for example `Sound:SlideBack`, `Sound:SlideForward`, `Sound:MagRelease`, `Sound:MagIn`, `Sound:MagPouch`, `Sound:SafetyClick`, `Sound:DryFire`, `Sound:BoltForward`

## Actions per gun

| Action | What it is |
|---|---|
| `Fire` | Trigger press and whole-gun recoil. The game cycles the slide or bolt in code from recoil, so there is no slide, barrel, bolt or dust-cover track (on the last round the code locks it back). |
| `FireDA` | M9 double-action first shot: long trigger pull with the hammer rising, then the break. |
| `DryFire` | Trigger press on an empty chamber (hammer falls with a click). |
| `RackSlide` (pistols) / `ChargeHandle` (rifles) | Pull the slide or charging handle fully back and let it go. Pauses at the rear while the key is held. |
| `LockOpen` | Pull back and lock the slide or bolt open (not the AK, which has no hold-open). |
| `SlingshotRelease` (pistols) / `ChargeFromLock` (rifles) | From locked open: pull slightly back and let it fly forward. |
| `SlideRelease` (pistols) / `BoltRelease` (rifles with a catch) | Drop a locked slide or bolt with the slide stop or bolt catch. |
| `MagOut`, `MagDrop`, `MagIn` | The halves of a reload, for the full manual controls: catch and stow the old mag, or let it fall; fetch a fresh one and seat it. |
| `ReloadTactical` | Old mag to the pouch, fresh mag in, round still chambered. |
| `ReloadEmpty` | Slide or bolt open: drop the mag, insert a fresh one, release (AK: charge). |
| `MagCheck` | Pull the mag, look at it (pistols bring it up to the eye; rifles tip it to see the top round), put it back. Pauses in view while held. |
| `PressCheck` | Open the action a little to see brass in the chamber, then close it. Pauses while held. |
| `SafetyOn`, `SafetyOff` | Thumb or finger works the safety or selector. |
| `Decock` | M9: the slide lever drops the hammer safely, then goes back to fire. |
| `TapRack` | Clear a failure to fire: tap the mag up, then rack. |
| `ClearStovepipe` | Rack the stuck case out. |
| `ClearDoubleFeed` | Lock open, strip the mag, rack three times, mag in, rack. |
| `Draw`, `Holster` | Pistols from the hip holster; rifles between low ready and shouldered. |
| `Inspect` | Tilt and turn the gun to look it over (idle flavour). |

Not every gun has every action: the generator writes only the ones that apply, and the game asks `HasAction(name)`.
